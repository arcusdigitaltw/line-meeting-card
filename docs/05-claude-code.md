# 05・用 Claude Code 把它改成你的

這個專案是拿來改的。你不需要會寫程式，但需要會「講清楚你要什麼」，還有「確認它真的做對了」。

## 安裝與啟動

需要 Node.js 18 以上。

```bash
npm install -g @anthropic-ai/claude-code
cd line-meeting-card
claude
```

第一次會請你登入。進去之後，它已經讀過專案根目錄的 [`CLAUDE.md`](../CLAUDE.md)，知道這個專案的結構、哪些地方不能亂動、改完要跑什麼檢查。你也可以用桌面版或 VS Code 外掛，用法一樣。

## 三個好習慣

**一、先叫它看，再叫它改。** 第一句話不要直接下指令，先問：

```
先讀 lib/card.js 和 public/share.html，用白話告訴我「按下分享」之後發生了哪些事。
```

它講得出來，代表它看懂了，後面改起來比較不會歪。

**二、一次只改一件事。** 「加講者欄位」和「換資料庫」分兩次講。混在一起出問題時，你不知道是哪個改動造成的。

**三、每次都要它自己驗證。** 句尾加上：

```
改完跑 npm test 和 npm run smoke，把結果貼給我。
```

它說「改好了」不算數，測試通過才算。

## 可以直接複製的指令

### 改卡片長相

```
邀請卡的主色改成 #E1306C，最上面那行小字從「會議邀請」改成「線上講座」。
改完跑 npm test，再跑 npm run flex 把 JSON 給我，我要貼到 LINE 的模擬器看。
```

### 加一個欄位

```
我要在會議多一個「講者」欄位：
1. 後台表單可以填
2. 邀請卡上「主辦」那一列的上面多一列「講者」
3. 邀請頁也要顯示
沒填的時候卡片上不要出現這一列（不能放空字串，LINE 會拒收）。
照 CLAUDE.md 的規則做，改完跑測試。
```

注意括號裡那句。把你知道的雷直接告訴它，比事後抓錯快。

### 換資料庫

```
把 lib/store.js 從 JSON 檔換成 SQLite（用 better-sqlite3）。
list、get、getByToken、create、update、remove 這六個函式的用法不能變，server.js 不要動。
寫一支 scripts/migrate-json-to-sqlite.js 把現有的 data/meetings.json 搬過去。
改完跑 npm test 和 npm run smoke。
```

### 加提醒功能

```
我想在會議開始前 1 小時，自動用 LINE 官方帳號推播提醒給主辦人。
先不要寫程式。告訴我需要申請什麼、要多哪些環境變數、會改到哪些檔案、有什麼風險，我確認後再動手。
```

大一點的功能，先要計畫再要程式。

### 排錯

```
我在手機點分享連結，選了人按傳送之後什麼都沒發生，畫面下方的小字最後一行是：
> error INVALID_ARGUMENT ...
幫我找原因。
```

把畫面上看到的原文貼給它，不要用自己的話轉述。

## 什麼時候不要相信它

- **它說 LINE 後台某個按鈕在哪裡。** 後台會改版，它的記憶可能是舊的。以你眼前的畫面和 [LINE 官方文件](https://developers.line.biz/en/docs/liff/) 為準。
- **它說 Recall.ai 的某個參數可以這樣寫。** 請它附上官方文件的連結，或先用一場測試會議試過。
- **它想把金鑰寫進程式碼。** 金鑰只能放 `.env`。看到它把 `RECALL_API_KEY` 的值貼進任何 `.js` 檔，立刻叫它改回去。
- **它跳過測試。** 沒貼出 `npm test` 的結果，就當作沒測。

## 把你踩到的雷記下來

發現新的坑（例如某種寫法在 iPhone 上會壞），請它寫進 `CLAUDE.md` 的「踩過的雷」那一段：

```
把剛剛發現的問題寫進 CLAUDE.md 的「踩過的雷」：現象、原因、正確做法，各一句話。
```

下次開新的對話，它就不會再犯同樣的錯。`CLAUDE.md` 是你和它共用的筆記本。
